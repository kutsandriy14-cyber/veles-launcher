# Управление сборками

Launcher читает все публичные Releases из `kutsandriy14-cyber/veles-modpack-releases`. В список попадают только релизы, которые содержат оба обязательных asset-файла: `build.zip` и `build-info.txt`.

Активность и приоритет хранятся в тексте GitHub Release:

```text
VELES_ACTIVE=1
VELES_PRIORITY=1
```

`VELES_ACTIVE=1` означает, что сборка поддерживается сервером. `VELES_ACTIVE=0` означает, что сборка сохранена в истории, но Launcher не выбирает её для запуска. Меньшее значение `VELES_PRIORITY` ставит сборку выше остальных. Publisher при действии «Поставить первой» делает выбранный Release активным с приоритетом `1`, а остальные релизы помечает неактивными.

Главный экран Launcher сохраняет структуру утверждённого референса и показывает только текущую активную сборку. Полный список доступен через блок «Сборка и обновление» и отображает название, версию, состояние `АКТИВНА` или `НЕАКТИВНА` и приоритет.

Publisher умеет автоматически читать metadata из ZIP, показывать технические значения только для чтения, создавать Release, менять название/активность/приоритет, удалять Release вместе с tag и повторно публиковать удалённую версию после исправления архива.

Новый Launcher release не публикуется автоматически после изменений. Сначала проверяются Windows CI и визуальный экран, затем релиз создаётся отдельно после утверждения интерфейса.
