# Пользовательская проверка Veles Launcher

Проверка выполняется глазами игрока, без предположений о внутренней реализации.

| Сценарий | Ожидаемый результат |
|---|---|
| Первый запуск без опубликованной сборки | Видно спокойное сообщение «Сборка сервера пока не опубликована», версия отображается как `—`, запуск отключён, технический текст GitHub API не показывается. |
| Открытие главного окна | Тёмные плоские карточки, оранжевый акцент, ровные отступы; название и параметры сборки не обрезаются и не накладываются. |
| Проверка актуальности | Лаунчер получает последнюю сборку из публичного репозитория; запуск блокируется, если сборка отсутствует или устарела. |
| Установка сборки | Архив скачивается и распаковывается встроенными средствами .NET без 7-Zip и без ручных команд; сервер появляется в `servers.dat`. |
| Java | Лаунчер проверяет Java внутри экземпляра, автоматически устанавливает/обновляет её из доверенного архива с SHA-256 и показывает понятный статус. |
| Настройки | Игрок может выбрать допустимый объём RAM и путь экземпляра; параметры сохраняются локально и не требуют командной строки. |
| Прямой запуск | Игра запускается через `javaw.exe` и валидированный `launch.json`; `start.bat`, `cmd.exe`, произвольные shell-команды и поле LAUNCH_COMMAND отсутствуют. |
| Неполный релиз | При отсутствии `launch.json` или встроенной Java запуск не происходит; показывается «Релиз сборки опубликован неполностью». |
| Обновление | Новая сборка устанавливается атомарно; при ошибке старая рабочая сборка не теряется. |
| Админ-публикация | Панель принимает ZIP, единый адрес `IP:PORT`, фиксированный список модлоадеров и проверяет launch.json/Java до создания Release. |

## Критерий публикации

Новая версия не публикуется, пока локальная проверка, core-тесты, Windows CI и содержимое обоих установщиков не подтверждены. Реальный запуск Forge на Windows требует тестового `build.zip` с настоящей launch-метаданной и Java runtime; до этого проверяется отказоустойчивый путь с понятной ошибкой.
